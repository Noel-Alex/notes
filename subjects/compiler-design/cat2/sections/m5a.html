M5

Code optimization · improve resources without changing meaning

Optimization transforms intermediate/target code so the final program can run faster or use fewer resources.

Correctness

The optimized program must preserve the meaning of the original program.

Performance

Optimization should improve speed/performance and/or resource usage such as CPU/memory.

Reasonable compile time

The optimization process itself should not make compilation unreasonably slow.

Machine-independent vs machine-dependent optimization
TypeSource description
Machine independentTransforms intermediate code to obtain better target code; does not depend on CPU registers or absolute memory locations.
Machine dependentPerformed with target-machine details such as registers/architecture and may involve absolute memory references.
Compile-time evaluation

Folding: perform constant computation during compilation. Source example: in length=(22/7)*d, evaluate 22/7 at compile time.

Constant/variable propagation: substitute known values before run time. Source example: pi=3.14, r=5, Area=pi*r*r → compiler can substitute 3.14 and 5 and precompute constant work.

M5

Principal sources of optimization

The source divides machine-independent optimization into function-preserving transformations and loop optimizations.

Function preserving

Common subexpression elimination · Copy propagation · Dead-code elimination · Constant folding.

Loop optimization

Code motion · Induction-variable elimination · Reduction in strength.

1 · Common subexpression elimination

If an expression was already computed and none of its operands changed, reuse the previous result instead of recomputing it.

t1 = 4*i t2 = a[t1] t3 = 4*j t4 = 4*i
→
t1 = 4*i t2 = a[t1] t3 = 4*j use t1 instead of recomputing 4*i
2 · Dead-code elimination

A value/code region is dead if its result can never affect program output or future computation. Source example: i=0; if(i==1){a=x+5;} — the branch is unreachable under the shown fixed value and can be eliminated.

3 · Code motion / loop-invariant computation

Move a computation outside a loop when its value does not change between iterations. Source examples move N=max-1 or b=x+y before the loop instead of recalculating every iteration.

4 · Copy propagation
x = pi; area = x*r*r   →   area = pi*r*r

Replace uses of a copied variable with the original value/name when safe.

5 · Reduction in strength + induction-variable idea

Replace expensive repeated operations with cheaper equivalent ones. The source emphasizes multiplication→addition and exponentiation→multiplication when valid.

for(i=1;i<=50;i++) { count = i * 7; }
→
temp = 7; for(i=1;i<=50;i++) { count = temp; temp = temp + 7; }

count still takes 7,14,21,… but a repeated multiply is replaced by addition. Induction-variable elimination then removes redundant variables that change in a predictable linear relationship with a basic loop variable.

6 · Constant folding

If an expression's value is constant, replace the expression with the computed constant. Source example: pi=22/7 → pi≈3.14 in the slide's illustration.

M5

Global data-flow analysis · facts moving through the flow graph

Optimization often needs information from the whole program, not just one statement. Data-flow equations describe how facts are generated, killed and propagated.

Definition point

A program point that defines a data item, e.g. x=3.

Reference point

A point that uses/references a data item, e.g. y=x.

Evaluation point

A point that evaluates an expression, e.g. z=a*b.

Four data-flow properties · do not mix them up
PropertyQuestion it answersUse named in source
Reaching definitionCan this definition reach this point along some path without being killed by a redefinition?Variable/constant propagation.
Available expressionHas this expression already been evaluated on all reaching paths, with neither operand modified afterward?Common-subexpression elimination.
Live variableWill the current value of this variable be used on some path before it is redefined?Register allocation and dead-code elimination.
Busy expressionWill the expression be evaluated along some path before any operand is redefined?Code movement optimization.
Reaching-definition GEN/KILL equations shown in the source

For a single statement S containing a new definition d of variable a:

gen[S] = {d}
kill[S] = Dₐ − {d}
out[S] = gen[S] ∪ (in[S] − kill[S])

For a sequence S = S1 ; S2, the slide gives:

gen[S] = gen[S2] ∪ (gen[S1] − kill[S2])
kill[S] = kill[S2] ∪ (kill[S1] − gen[S2])
in[S1] = in[S]
in[S2] = out[S1]
out[S] = out[S2]
If/else and loop equations shown in the supplied slide

If/else structure:

gen[S] = gen[S1] ∪ gen[S2]
kill[S] = kill[S1] ∩ kill[S2]
in[S1]=in[S], in[S2]=in[S]
out[S] = out[S1] ∪ out[S2]

Loop structure as written on the source slide:

gen[S] = gen[S1]
kill[S] = kill[S1]
in[S1] = in[S] ∪ gen[S1]
out[S] = out[S1]
Path definition

A path p1,…,pn is a sequence of program points connected either by statement order inside a block or by control-flow edges between the end of one block and the beginning of a successor block. Reaching/live/available/busy definitions all depend on which facts survive along these paths.
