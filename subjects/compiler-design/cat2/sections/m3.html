M3

Syntax-Directed Definition · attach meaning to grammar

Module 3 is much easier if you stop thinking “new grammar” and think “same parse tree, but values/types/code now flow through it.”

SDD

SDD = CFG + attributes + semantic rules

Attributes belong to grammar symbols; semantic rules belong to productions.

Synthesized attribute

A node computes its value from its children (and the node itself). Information flows mainly up the parse tree.

Inherited attribute

A node gets information from its parent and/or siblings. In the L-attributed restriction used later, inherited information comes only from the parent and left siblings.

M3

Annotated parse trees · every node shows its attribute value

A parse tree plus evaluated attributes is an annotated parse tree.

For the source expression 3 * 5 + 4:

  1. digit 3 gives F.val=3.
  2. digit 5 gives F.val=5.
  3. T→T₁*F computes 3×5=15.
  4. E→T carries 15 upward.
  5. digit 4 gives T.val=4.
  6. E→E₁+T computes 15+4=19.

Why evaluation is bottom-up here

Every parent attribute depends on child attributes. Therefore children must be known before their parent can be evaluated. This is exactly why S-attributed definitions fit bottom-up parsing naturally.

M3

Dependency graph · turn semantic dependencies into an ordering problem

The graph answers: “Which attribute must be known before which other attribute?”

  1. Create one dependency-graph node for every attribute instance on the parse tree.
  2. For each semantic rule b = f(c₁,…,cₖ), draw directed edges cᵢ → b.
  3. Any valid topological order of the resulting acyclic graph is a valid attribute-evaluation order.

Source definition of topological sort

A topological sort orders graph nodes so that whenever there is an edge mᵢ→mⱼ, mᵢ appears before mⱼ. That ordering is precisely what you need to evaluate attributes without using a value before it exists.

M3

L-attributed definitions · inherited data may come only from the left

The source restriction is what makes left-to-right evaluation practical.

For A → X₁ X₂ … Xₙ, an inherited attribute of Xⱼ may depend only on:
1) inherited attributes of A, and 2) attributes of X₁ … Xⱼ₋₁ to the left.

S-attributed

Only synthesized attributes. Natural for bottom-up evaluation. Semantic actions can be placed at the right end of productions.

L-attributed

Allows synthesized + inherited attributes under the left-dependency restriction. Supports left-to-right evaluation.

M3

Syntax-Directed Translation Scheme · actions are embedded in productions

Action position is now operational: when the parser reaches the action, it executes it.

SDD

High-level semantic specification. Rules are associated with productions but evaluation order may be hidden.

SDT

Semantic actions {…} appear inside production bodies. Their position determines execution order.

Infix → postfix SDT from the source
E → E + T { print('+') }
E → T
T → T * F { print('*') }
T → F
F → num { print(num.lexval) }

For 2+3*4, leaves print operands when reduced/visited, and operator actions run after their operands, producing postfix order 234*+.

Top-down vs bottom-up execution of SDT

The supplied part-2 semantic-analysis slides use the same postfix SDT to show both parser directions. A top-down parser encounters actions during a left-to-right parse-tree traversal; a bottom-up parser typically executes the semantic action associated with a production when that production is reduced. The intended output is the same.

Bottom-up evaluation of S-attributed definitions

The source shows synthesized values stored alongside parser-stack symbols. When a reduction A→XYZ occurs, the semantic action computes A's value from the attributes of X/Y/Z already on the stack. This is why synthesized attributes are especially convenient for LR parsing.
