Basic blocks and flow graphs · cut TAC at control-flow boundaries

A basic block is a maximal straight-line sequence: control enters at the beginning and leaves only at the end.

Leader rules1) The first statement is a leader. 2) Any target of a conditional/unconditional goto is a leader. 3) Any statement immediately following a goto/conditional goto is a leader.
  1. Mark every leader.
  2. For each leader, form a block from that leader through the statement immediately before the next leader (or end of program).
  3. Create one flow-graph node per basic block.
  4. Add edges for possible transfers of control between blocks.
Source loop TAC intuition
(1) prod = 0
(2) i = 1
(3) t1 = 4*i
(4) t2 = a[t1]
(5) t3 = 4*i
(6) t4 = b[t3]
(7) t5 = t2*t4
(8) t6 = prod+t5
(9) prod = t6
(10) t7 = i+1
(11) i = t7
(12) if i <= 20 goto (3)

Statement 1 is a leader; statement 3 is a branch target. Blocks become nodes in the flow graph, and the conditional jump creates the loop-back edge.

Transformations on basic blocks
The Module-5 Part-2 source divides them into structure-preserving and algebraic transformations.


Structure preserving
  1. Common-subexpression elimination.
  2. Dead-code elimination.
  3. Renaming temporary variables.
  4. Interchange of independent adjacent statements.
Algebraic
Use algebraic identities/equivalences to simplify expressions or replace expensive operations with cheaper equivalents.
x = x + 0 → x
x = x * 1 → x


Temporary renaming
Changing t=b+c to u=b+c and consistently replacing all uses of that particular t with u does not change the basic block's value. The source notes that an equivalent block can be written so each statement defines a new temporary.


Interchanging independent adjacent statements
t1 = b+c
t2 = x+y
These can be swapped only if neither statement depends on a value defined/used by the other. The source calls a block that permits all legal statement interchanges a normal-form basic block.

Peephole Optimization · your Module-5 stopping point
A small moving window (“peephole”) examines short target-code sequences and replaces them with shorter or faster equivalent sequences.


1 · Redundant loads/stores
Delete a load/store whose effect is already available and unchanged.
MOV R0,x
MOV x,R0
→ second instruction removable
2 · Unreachable code
Remove target instructions that can never be executed.
3 · Flow-of-control optimization
Collapse needless jump chains and unnecessary gotos.
4 · Algebraic simplification
Remove x=x+0, x=x*1 and use reduction in strength where applicable.
5 · Machine idioms
Replace generic instruction sequences by efficient target-machine instructions.
i=i+1 → INCR i
i=i-1 → DECR i
