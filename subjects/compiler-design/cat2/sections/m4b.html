M4

Assignment translation · newtemp, lookup and type conversion

The source gives syntax-directed rules that build TAC as expressions are reduced.

E → E1 + E2 {
  E.place = newtemp;
  emit(E.place = E1.place + E2.place);
}
E → -E1 {
  E.place = newtemp;
  emit(E.place = uminus E1.place);
}
S → id := E {
  p = lookup(id.name);
  if p ≠ nil emit(p := E.place); else error;
}
Type conversion in assignments · source example

For x := y + i*j, assume x,y are real and i,j are integer:

t1 = i int* j
t3 = inttoreal(t1)
t2 = y real+ t3
x  = t2

The semantic rule chooses integer or real operators based on operand types and inserts inttoreal when one side is integer and the other is real.

Reusing temporary names

Temporaries consume storage. The source notes that temporary lifetimes in expression evaluation are nested, so newtemp can be implemented to reuse temporaries whose values are no longer needed rather than allocating an unlimited stream of new names.

M4

Boolean expressions and control flow · value code vs jumping code

The source teaches two completely different representations of “true/false”. Know both.

Numerical representation

Compute Boolean values like arithmetic: commonly 1=true and 0=false.

a or b and not c
t1 = not c
t2 = b and t1
t3 = a or t2

Flow-of-control / short-circuit

Do not necessarily compute a Boolean temporary. Jump directly to E.true or E.false.

if A<B goto E.true
goto E.false
Short-circuit logicFor a or b, once a is true there is no need to evaluate b. For a and b, once a is false there is no need to evaluate b.
Source Boolean expression · a<b or c<d and e<f
if a < b goto Ltrue
goto L1
L1: if c < d goto L2
goto Lfalse
L2: if e < f goto Ltrue
goto Lfalse

The precedence in the source is not highest, then and, then or.

Flow-of-control statement shapes

if E then S1

E.true jumps into S1; E.false continues to S.next.

if E then S1 else S2

E.true enters S1, E.false enters S2, and both branches must continue to the code after the whole statement.

while E do S1

Evaluate E, enter body on true, jump back to the test after the body, exit on false.

M4

Backpatching · generate the jump now, fill the target later

This solves forward-jump targets that are unknown when the jump instruction is first emitted.

makelist(i)

Create a list containing the index of one unresolved jump instruction.

merge(p1,p2)

Concatenate two lists of unresolved jumps.

backpatch(p,i)

Fill every blank target in list p with target instruction i.

nextinstr / nextquad

Index of the next instruction that would be emitted.

truelist

Jumps that must eventually point to the code for the true outcome.

falselist

Jumps that must eventually point to the false outcome.

nextlist

Jumps that should continue at the instruction after a completed statement.

Backpatching control-flow statements
The supplied guide extends the same lists to if, if-else, while and statement lists. Marker M captures where a branch/body begins; marker N may emit an unresolved goto used to jump past an else branch. The algorithm is always the same: create unresolved jump lists early, then patch them as soon as the correct target becomes known.
