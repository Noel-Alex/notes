CLR prerequisite · only what you need to start LR(1)

CLR = Canonical LR using LR(1) items. An LR(1) item adds a lookahead to the familiar dotted production.

LR(1) item

[A → α · β, a]

The dot shows parsing progress. a is the lookahead terminal on which a completed item may reduce.

GOTO

GOTO(I,X): move · across X, then take closure

If an item contains A→α·Xβ, moving over X gives A→αX·β.

CLR closure lookahead

[A→α·Bβ, a] ⇒ B-items get lookahead FIRST(βa)

This is the critical difference in the source's CLR construction: lookahead is propagated precisely, not by attaching a whole FOLLOW set.

Source lookahead example · S → CC, C → cC | d

Start with [S′→·S, $]. Closure adds [S→·CC, $]. For the first C, β is the second C, so the new C-items receive:

FIRST(C$) = FIRST(C) = { c, d }

Therefore closure contains [C→·cC, c|d] and [C→·d, c|d]. Later, when β is empty, the lookahead is inherited directly from the parent item.

Canonical LR(1) · build the states, then the table

Source grammar: S → AA, A → aA | b. This is the cleanest way to see why CLR can separate contexts that LR(0)-core-only methods cannot.

  1. Augment: add S′→S.
  2. I0: begin with [S′→·S,$] and compute LR(1) closure using FIRST(βa).
  3. Build GOTO graph: for every grammar symbol reachable after a dot, move the dot and close again.
  4. Table: terminal transitions become shift; completed A→α· items reduce only on their LR(1) lookaheads; [S′→S·,$] gives accept; nonterminal transitions fill GOTO.
  5. Parse: use the ACTION/GOTO table exactly like an LR stack machine.

Conflict rules · what makes an LR table invalid
The source ends the CLR/LALR material with practical conflict observations.


Reduce/Reduce conflict
If one state has two completed productions and the same terminal is a valid reduction lookahead for both, the ACTION cell gets two reductions.
Shift/Reduce conflict
If a state can shift on terminal a and also contains a completed production whose reduction lookahead is a, the same ACTION cell asks for both shift and reduce.


LALR warning from the sourceMerging CLR states unions lookaheads. Even if the CLR collection itself separates contexts, the union created by an LALR merge can produce a reduce/reduce conflict.


What not to do in the exam
  • Do not attach every FOLLOW symbol to every CLR reduction. CLR uses the item's actual lookahead.
  • Do not merge CLR states just because their lookaheads differ; merge only when their LR(0) cores are identical.
  • Do not forget to union lookaheads after merging.
  • Do not reduce a completed LR(1) item on terminals not in its lookahead set.
