Intermediate Code Generation · lower high-level syntax into a portable form

The source motivates an intermediate language as a machine-independent layer between semantic analysis and target-code generation.

Syntax treeNatural hierarchical structure of the source expression.
DAGLike a syntax tree, but shared common subexpressions can point to one node.
PostfixLinearized tree: operands first, operator after operands.
Three-address codeSequence of small statements with at most three addresses.
Benefits in the sourceDifferent machine backends can reuse the same front end, and machine-independent optimization can operate on the intermediate representation before final target-code generation.
Syntax tree vs DAG

A syntax tree duplicates repeated subexpressions. A DAG identifies common subexpressions and reuses the same node.

Source expression: a + a*(b-c) + (b-c)*d. The subexpression (b-c) appears twice; a DAG can represent it once and let both parents point to the same node.

M4

Three-Address Code · make every operation explicit

A typical statement is x = y op z. Complex source expressions are decomposed using compiler-generated temporaries.

a = b + c + d
t1 = b + c
t2 = t1 + d
a = t2
Three representations · quadruple, triple, indirect triple

Source expression: x = -a*b + -a*b

t1 = -a
t2 = t1 * b
t3 = -a
t4 = t3 * b
t5 = t2 + t4
x  = t5

Quadruple

Fields: (op, arg1, arg2, result). Temporaries appear explicitly as results.

Triple

Fields: (op, arg1, arg2). A temporary result is referred to by the position/number of the statement that computed it.

Indirect triple

Keep the triple table but add a separate list of pointers to triples. Reordering can be done by rearranging pointers rather than moving triple records.

Worked source request · a + -(b+c)

The notes explicitly ask for all four forms: syntax tree, quadruples, triples and indirect triples. The systematic process is: build tree → emit TAC bottom-up → write each emitted operation into the chosen record representation.

M4

Declarations, storage layout and arrays

Declarations update the symbol table with type and relative address information; an offset tracks the next available storage location.

mktable(previous)

Create a new symbol table and link it to an enclosing table.

enter(table,name,type,offset)

Create an entry containing the identifier's type and relative address.

addwidth(table,width)

Store the total width of declarations associated with the table.

2D array declaration semantic information
D → T id [N1][N2]
D.type = array(N1.val, array(N2.val, T.type))
D.rows=N1.val; D.cols=N2.val
D.elements=N1.val×N2.val
D.width=D.elements×T.width

Source widths include int=2, float=4, char=1 in the shown grammar.

Array addressing formulas

1D with lower bound low:

Address(A[i]) = base + (i-low)×w

The source rewrites this as i×w + (base-low×w) so the constant part can be precomputed.

2D row-major:

base + ((i1-low1)×n2 + (i2-low2))×w

If indices are zero-based, this simplifies to:

base + (i×number_of_columns + j)×w
2D array TAC example
