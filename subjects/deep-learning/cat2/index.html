M3

CNN foundations · why convolution exists

Module 3 begins by contrasting ordinary fully connected ANNs with image structure, then builds the CNN layer stack from local connectivity and weight sharing.

Image representation

Grayscale images are 2-D arrays; color images use multiple channels such as RGB. Each spatial cell stores intensity/value information. The slides use dimensions such as 28×28×1 and 100×100×3.

Why plain ANN is inefficient

Flattening a large image directly into a dense network creates huge parameter counts and ignores local spatial structure such as edges, corners and textures.

CNN solution

Local connectivity: a filter sees a small receptive field. Weight sharing: the same filter weights slide across locations. This lets one learned detector search the entire image.

Kernel / filter · what it actually does

The smaller WIN slides define a kernel as a small learned weight matrix that slides over the input. At every location:

  1. Place the kernel over a local region.
  2. Multiply input and kernel values element-by-element.
  3. Sum the products.
  4. Store that scalar in the output feature map.
  5. Slide to the next valid location and repeat.

Different kernels can act as edge/texture/shape detectors. The source names simple edge filters, Sobel kernels, Gaussian-blur kernels and pooling kernels as examples of filter ideas; CNN convolution kernels are learned during training.

RGB convolution + multiple filters

For an RGB input, a convolution filter spans all input channels: e.g. a 3×3 spatial filter over RGB is 3×3×3. The dot product across the full depth produces one scalar per spatial position.

If one filter produces one feature-map channel, then K filters produce K output channels. The source example states that if a 6×6 input convolved with 3×3 gives a 4×4 spatial map, then 10 filters give 4×4×10.

Local connectivity · exact parameter example from the source

The main Module-3 PDF gives a tiny network specifically to show why local connectivity matters. There are 7 input units and 3 hidden units.

Global connectivity

Every hidden unit connects to every input unit.

3 hidden × 7 input = 21 parameters

Local connectivity

Each hidden unit sees only a local receptive field of 3 inputs.

3 hidden × 3 local inputs = 9 parameters

Meaning: a CNN does not need every detector to look at the entire image. Local patterns such as edges, corners and textures can be detected from small neighborhoods.

Weight sharing · exact 9 → 3 parameter example

The next source example keeps the local receptive-field idea but compares using separate weights at every location with reusing one filter everywhere.

Without weight sharing: 3 × 3 = 9 distinct weights
With weight sharing: 3 × 1 = 3 shared weights

Why it matters: the same local feature detector can be useful anywhere in the image. Sharing the kernel reduces parameters and contributes to translation tolerance.

Input representation · binary, grayscale and RGB
  • Binary image: the source describes two intensity states.
  • Grayscale: one intensity value per pixel → H×W×1.
  • RGB: three values per pixel → H×W×3.

A convolution filter over RGB spans all three channels. A 3×3 RGB filter therefore has shape 3×3×3 before counting bias.

M3

Convolution, padding and stride · calculate dimensions without hesitation

This is one of the most mechanical—and easiest to score—parts of Module 3.

Spatial output used throughout the slides: O = ((N + 2P − F) / S) + 1
N=input size · P=padding · F=filter size · S=stride
Rectangular inputsApply the same relation independently to height and width. The WIN slide's 6×7 input, 3×3 kernel, stride 2 example produces a 2×3 map.

No padding · stride 1

6×6 input, 3×3 filter:

6−3+1=4 ⇒ 4×4

Repeated valid convolution shrinks spatial size and can lose border information.

Padding

6×6 input, 3×3 filter, P=1:

6+2(1)−3+1=6 ⇒ 6×6

Padding preserves border participation and can preserve spatial size.

Stride

Stride is how many pixels the filter moves each step. Larger stride downsamples more aggressively and reduces compute/memory.

Padding typeWhat the source saysTypical result at stride 1
SAMEZeros are added around the input.Output spatial size maintained.
VALIDNo padding; filter used only where it fully fits.Output smaller than input.
Current Module-3 example · 32×32×3, 5×5, 6 filters

Without padding: N=32,F=5,S=1,P=0 → 28×28 spatial size. Six filters → 28×28×6.

With P=2: (32+4−5)+1=32 → 32×32×6.

M3

Pooling, activation, flatten and fully connected layers

Know what each layer changes: spatial dimensions, values, vector shape—or trainable parameters.

Max pooling

Reports the maximum in each local neighborhood. The source calls this the most common pooling operation.

Average pooling

Averages a neighborhood. The WIN slides say it retains more of the less-dominant information and can improve noise robustness.

L2-norm pooling

WIN pooling deck: square-root of the sum of squares inside the neighborhood; listed as a way to highlight important features and improve noise robustness.

Weighted pooling

The same deck also names weighted averaging based on distance from the central pixel.

Exact max-pooling example

Input 4×4:

3 1 1 3
2 5 0 2
1 4 2 1
4 7 2 4

With 2×2 max pooling, stride 2, the four neighborhoods produce:

5 3
7 4

For multi-channel feature maps, pooling is applied spatially per channel; the source illustrates 8×8×3 → 4×4×3.

Why pooling?

Downsampling reduces compute and memory, shortens training, controls overfitting, and provides some invariance to small translations/scale changes.

Pooling drawbacks

The source lists information loss and reduced spatial resolution; it warns that architecture choices must balance compression against fine detail.

Trainable params

Max/average pooling have 0 trainable weights/biases. They aggregate; they do not learn parameters.

Flatten → Fully Connected → Output

Flatten: reshapes H×W×C feature maps into a 1-D vector; it has 0 trainable parameters.

Fully connected: every input neuron connects to every output neuron; the last dense representation performs high-level reasoning/classification.

Output: the current Module-3 slides mention SVM/hinge-loss or Softmax/cross-entropy classification. For a C-class softmax output, the final layer has C output units.

Full non-linearity list actually named in the main Module-3 source

The architecture-component slide names Sigmoid, tanh, ReLU, PReLU, ELU and Swish as examples. The current material develops ReLU most directly; the other names are still part of the taught component list.

Purpose: activation introduces non-linearity after convolution so stacked layers can model complex functions rather than collapsing into one linear mapping.

AlexNet · what changed

2012 ImageNet winner; current slides use input 227×227×3 and the simplified chain:

CONV1 96@11×11,S4 → POOL → NORM → CONV2 256@5×5 → POOL/NORM → CONV3 384@3×3 → CONV4 384 → CONV5 256 → POOL → FC6 4096 → FC7 4096 → FC8 1000

Features emphasized across the ZIP: ReLU, overlapping max-pooling, local response normalization in the original architecture, heavy data augmentation, dropout/L2-type regularization in the older deck, SGD+momentum, and distributed two-GPU training.

Counting convention inside the ZIPThe older WIN slide calls AlexNet “7 layers (5 Conv + 2 FC)” because it treats the final output separately; the current PDF lists 5 convolution + 3 fully connected (FC6, FC7, FC8). For an exam, describe the actual layer chain and you avoid the naming ambiguity.
VGG · why stacks of 3×3?

VGG-16/VGG-19 use a simple sequential pattern: mostly 3×3 convolution, stride 1, pad 1, with 2×2 max-pooling, stride 2.

The source's key reasoning: three stacked 3×3 stride-1 convolutions have an effective receptive field of 7×7, but give more non-linearities and fewer parameters than one 7×7 layer at the same channel width.

The PDF states VGG is parameter/memory heavy—about 138M parameters for VGG-16, with early convolution activations dominating memory and late FC layers dominating parameter count.

GoogLeNet / Inception · parallel filters + bottlenecks

An Inception module applies several operations in parallel—1×1, 3×3, 5×5 convolutions and pooling—then concatenates outputs depth-wise. This captures features at multiple scales.

Naively doing all branches is expensive. The source therefore inserts 1×1 bottleneck convolutions before larger filters to reduce channel depth. A 1×1 conv preserves spatial H×W while projecting depth.

Current slides give an example reducing a naive Inception block from about 854M operations to about 358M operations after bottlenecks.

GoogLeNet also uses global average pooling instead of large FC stacks and auxiliary classifiers to inject gradients into lower layers. The slides quote roughly 5–6.8M parameters depending on the summary slide.

ResNet · residual learning
Residual block: y = F(x) + x

As networks become very deep, the slides emphasize vanishing gradients and the degradation problem. Skip/identity connections create a direct path for information/gradients and make very deep networks easier to optimize.

Source architecture points: stack residual blocks; a basic block uses two 3×3 conv layers; periodically downsample with stride 2 while increasing filters; use global average pooling near the end; common depths include 18,34,50,101,152.

GoogLeNet 1×1 convolution · exact source shape intuition

The GoogLeNet slides show a 28×28×256 input followed by 128 filters of size 1×1×256. A 1×1 convolution performs a depth-wise dot product at every spatial location.

28×28×256 → 1×1 conv with 128 filters → 28×28×128

Spatial H×W stays the same while channel depth is reduced, making later 3×3 and 5×5 branches cheaper.

Module 3 safety net · the rest of the ZIP

Stacking convolutional layers

Earlier layers learn primitive patterns such as edges; deeper layers combine them into shapes and object-level features. Benefits named in the WIN deck: more complex features, better accuracy and robustness. Challenges: more computation, higher overfitting risk and harder architecture/hyperparameter selection.

Forward / back propagation in CNN

The WIN deck's simple CNN is: image → convolution → ReLU → max-pool → flatten → dense output. It explicitly labels backpropagation through convolution, max-pooling and flatten, and notes that convolution/dense weights are the trainable parameters while ReLU/pooling/flatten have no learned weights.

A tiny source diagram counts 15 trainable parameters for a 3×3 convolution (9 weights + bias) followed by a dense connection from a 4-element pooled/flattened vector to one neuron (4 weights + bias).

CNN advantages / disadvantages

Advantages emphasized: automatic feature extraction, local connectivity/weight sharing, fewer parameters than naive dense image models, hierarchical features and strong image/spatial performance. Disadvantages/risks include compute/memory cost, architecture tuning and information loss from aggressive downsampling.

Applications listed across Module 3

Image classification, object/feature recognition, computer vision tasks, medical/image analysis, autonomous/industry use cases and other sectors. The slides also connect CNN feature extractors with transfer learning.

M4

RNN fundamentals · the network carries state through time

Module 4 shifts from spatial structure to sequence structure. The defining idea is the hidden state/memory passed from one time step to the next.

Why RNN?

Feed-forward networks do not naturally carry previous sequence context. RNNs are designed for sequential data such as text, speech, video and time series.

Hidden state

The current hidden state combines the current input and previous hidden state using shared weights. The same recurrent computation repeats at every time step.

Parameter sharing

The same input/recurrent/output weight matrices are reused across time, reducing parameter growth relative to giving every time step independent weights.

hₜ = tanh(Wₕₕ hₜ₋₁ + Wₓₕ xₜ)    (bias may be included)
yₜ = Wₕᵧ hₜ    (then apply the task's output activation if required)
One → One
single input, single output; source example: ordinary image classification.
One → Many
single input generates a sequence; image captioning / music generation.
Many → One
sequence → one decision; sentiment/language/emotion/spam classification.
Many → Many
sequence → sequence; equal length for sequence tagging/NER; unequal length for translation.
RNN vs CNN in the source

The Module-4 deck frames RNNs as better suited to temporal/sequential data and CNNs as spatial image models. RNN results feed back into future recurrent computation; CNNs are feed-forward feature extractors with filters/pooling.

Applications + limitations

Applications named include stock/time-series analysis, forecasting, translation, NLP, speech recognition, image captioning and sequence classification. Limitations listed: sequential computation is slow, long sequences are difficult for vanilla tanh/ReLU RNNs, future context is unavailable in a one-directional RNN, training is complicated, and gradients can vanish or explode.

Why the source moves from ANN/CNN to RNN

The first RNN slides separate two problem families:

Problem family 1 → CNN

Image recognition and very high-dimensional spatial inputs are used to motivate CNN-style processing and parameter reduction.

Problem family 2 → RNN

Time series, share-market analysis, profit forecasting, language translation, image captions and NLP require sequence context / memory. The source says a plain ANN considers the current input and lacks memory.

RNN merits and limitations · complete current-source points

Main benefit: hidden state remembers sequence information, and the same parameters are reused at each time step.

  • Recurrent computation is slow because processing is sequential.
  • Vanilla tanh/ReLU RNNs struggle with long sequences.
  • A one-directional RNN cannot use future data when computing the current state.
  • Training is complicated.
  • Exploding gradients can make weights unstable.
  • Vanishing gradients can make updates too small to preserve old context.

=(0.6640−0.5)(0.6640)+(0.6253−1.0)(0.6253)

Reconstruction x̂

 
Encoder: reduces dimensionality and captures important features. Bottleneck: compressed knowledge representation. Decoder: expands from the code and tries to reconstruct the original input as closely as possible.

 
The source says the training loss is typically a reconstruction loss such as MSE for continuous data or binary cross-entropy for binary data.


 

  
Convolutional AE
Encoder uses conv layers; decoder uses deconvolution/upsampling/transposed-convolution style layers. Useful for image compression, denoising and feature extraction.

  
Variational AE
Learns a probability distribution in latent space rather than a single fixed code; source mentions Gaussian latent variables and KL divergence as an extra loss term.

  
Denoising AE
Add noise to the input during training and reconstruct the original clean input. This prevents trivial copying and forces useful features.

  
Deep AE
Multiple encoder/decoder layers learn more complex, abstract representations than a shallow bottleneck.

 


 
Applications in source
Dimensionality reduction, image compression, anomaly detection, image denoising, feature extraction and generative/data-generation settings (especially VAE).


 
Autoencoder step-by-step working

  
  1. Input x enters the encoder.
  2. Encoder compresses x into a lower-dimensional code z.
  3. Decoder maps z to reconstruction x̂.
  4. Compare x̂ with x using reconstruction loss.
  5. Backpropagate the reconstruction error so the latent code preserves information needed to rebuild the input.

  
The source presents this as unsupervised representation learning.

Encoder
Embeds the input, processes it through recurrent layers (or transformers in modern variants), and accumulates essential information into a fixed-size context vector in the source's classic explanation.

  
Decoder
Uses the context vector and previous generated output to produce the target sequence one step at a time. A softmax output can generate token probabilities.

 


 
Source build workflow

  
  1. Prepare paired source/target sequence data and preprocess/tokenize.
  2. Define encoder, decoder, embeddings; optional attention; choose loss/optimizer.
  3. Train, validate and test; tune hyperparameters / early stop as needed.
  4. Inference pipeline: preprocess input → encoder → decoder output; beam search is named as an optional generation improvement.
  5. Fine-tune/iterate; deploy if required.

 


 
Applications named: machine translation, text summarization and speech recognition, plus other sequence-generation/mapping tasks.

M4
BERT · bidirectional Transformer encoder, MLM + NSP
The end of Module 4 gives BERT substantial coverage. Learn the architecture blocks, input representation and the two pre-training tasks exactly as presented.


 
BERT in one lineBidirectional Encoder Representations from Transformers: a Google pre-trained language model (2018) using the Transformer encoder so each token can use context from both directions.


 

  
Why BERT?
Large unlabeled text pre-training reduces reliance on scarce task-specific labeled data and avoids a purely one-directional context representation.

  
Two stages
Pre-training on unlabeled corpora with MLM + NSP, then fine-tuning on a specific downstream task.

  
Uses named
NER, question answering and sentiment analysis; the slides also discuss context-dependent word meaning.

 


 
BERT input representation

  
Input embedding = Token embedding + Positional embedding + Segment embedding

  
[CLS] is the first token and serves as an aggregate representation for classification. [SEP] separates sentence segments. Segment embeddings distinguish sentence A from sentence B; position embeddings encode order.

 


 
Transformer encoder inside BERT

  
  1. Multi-head self-attention learns relationships between all tokens.
  2. Feed-forward network adds non-linear token transformations.
  3. Add & Norm uses residual connections + layer normalization.
  4. Stacked encoder layers refine contextual token representations.

MLM · Masked Language Modeling

  
Select about 15% of tokens for prediction. For those selected tokens, the source gives the classic policy:

  
80% → replace with [MASK]
10% → replace with a random word
10% → keep unchanged

  
The encoder processes the whole context and the MLM head uses a feed-forward layer + softmax to assign probabilities to candidate vocabulary tokens.

  
80/10/10 masking simulator

 


 
NSP · Next Sentence Prediction

  
BERT receives sentence A and B with [CLS]/[SEP] framing and performs binary classification:

  
IsNext · B genuinely follows A
NotNext · B is an unrelated random sentence

  
The slides say pre-training uses 50% actual-next pairs and 50% random pairs. The [CLS] representation is passed to a classifier/softmax. The source example contrasts “They revised all the topics before the test” with “The sun sets in the west” after “The students prepared well for the exam.”

 


 
BERT pre-training flow · learn the order

  
  1. Create token sequence with special tokens such as [CLS] and [SEP].
  2. Add token + positional + segment embeddings.
  3. Pass them through stacked Transformer encoder layers with multi-head self-attention, feed-forward processing and Add & Norm.
  4. Use MLM to predict selected hidden/replaced tokens from bidirectional context.
  5. Use NSP to classify whether sentence B genuinely follows sentence A.
  6. Fine-tune the pretrained BERT model on a downstream labelled task such as sentiment analysis, NER or question answering.

 

 
MLM 15% + 80/10/10 rule

  
Select about 15% of tokens for the prediction task. Of those selected tokens: 80% are replaced by [MASK], 10% by a random word, and 10% remain unchanged.

Recursive Neural Networks · tree structure, not time sequence
Module 5 begins with a distinction that is easy to mix up.

 

  
RecNN
Designed for hierarchical/tree-structured data. Smaller child representations are recursively combined bottom-up into parent representations.
Source use cases: NLP sentence parsing/sentiment and computer-vision scene/object-part composition.

  
RNN
Designed for sequential/time-ordered data. The same recurrent computation carries state through the sequence.

 






 
M5
Long-term dependencies · the problem LSTM/GRU are solving
Vanilla RNNs may fail when relevant information is many time steps away.

 

  
Vanishing gradient
Gradients become extremely small during BPTT, so distant earlier information has almost no effect on weight updates. The source's language example: remembering “France” far back to predict “French.”

  
Exploding gradient
Gradients grow too large, causing unstable parameter updates/training. Module 5 later gives gradient clipping as a direct remedy.

 

 
The slides give two high-level solution families:

 
Gated units
LSTM / GRU
or
Attention
self-attention

 
Gates decide what to remember/forget; self-attention lets the model directly focus on relevant sequence positions regardless of distance.


 
Two long-term dependency examples from Module 5

  
France → French: “I grew up in France … I speak fluent French.” The model must retain “France” over a long distance.

  
Book → it: “John put the book on the table. Later, he picked it up.” Understanding “it” requires retaining “the book.”

  
The slides use these examples to motivate gated units and attention mechanisms.

M5
LSTM · three gates + a dedicated cell-state memory path
If you understand the role of Cₜ and can reproduce the six equations, you understand LSTM at the depth of these slides.


 
Inputs to one LSTM unitxₜ = current input · hₜ₋₁ = previous hidden/output state · Cₜ₋₁ = previous cell memory. Outputs: hₜ and Cₜ.


 
Forget gate
Decides what fraction of old cell memory Cₜ₋₁ should survive.

 
Input gate
Decides how much new candidate content should be written.

 
Output gate
Decides how much of the updated cell state should be exposed as hₜ.


 

 


 
All LSTM equations from the source

  
fₜ = σ(Wf xₜ + Uf hₜ₋₁ + b_f)

  
iₜ = σ(Wi xₜ + Ui hₜ₋₁ + b_i)

  
C̃ₜ = tanh(Wc xₜ + Uc hₜ₋₁ + b_c)

  
Cₜ = fₜ ⊙ Cₜ₋₁ + iₜ ⊙ C̃ₜ

  
oₜ = σ(Wo xₜ + Uo hₜ₋₁ + b_o)

  
hₜ = oₜ ⊙ tanh(Cₜ)

  
The source then shows a final dense/sigmoid classification step based on the last hidden state.

 


 
How to explain the gates in words

  
  1. Forget: scale old memory by fₜ.
  2. Propose new content: C̃ₜ creates candidate information.
  3. Write: input gate iₜ scales how much candidate enters.
  4. Update memory: add retained old memory + selected new memory.
  5. Expose: output gate oₜ decides how much of tanh(Cₜ) becomes hₜ.

 


 

  
Advantages in source
Learns long-term dependencies, preserves information over long sequences, avoids/mitigates vanishing/exploding-gradient behavior relative to simple RNNs, and handles complex sequential patterns.

  
Disadvantages in source
More computationally expensive, more memory/time, more parameters/operations, can overfit, and is harder to interpret than a simple RNN.

 

 
Applications named: language generation/modeling, voice recognition, sentiment analysis, handwriting recognition, video analysis and time-series prediction.






 
M5
GRU · simpler gated memory with no separate cell state
GRU keeps only hₜ and uses two gates: reset and update. The current Module-5 deck gives all four equations.


 
Source distinctionLSTM has separate Cₜ + hₜ and three gates; GRU has no separate cell state and uses hidden state hₜ with reset + update gates. The slides therefore describe GRU as simpler/faster to train.


 

 


 
All GRU equations from the source

  
zₜ = σ(Wz xₜ + Uz hₜ₋₁ + b_z)

  
rₜ = σ(Wr xₜ + Ur hₜ₋₁ + b_r)

  
h̃ₜ = tanh(Wh xₜ + Uh(rₜ ⊙ hₜ₋₁) + b_h)

  
hₜ = (1−zₜ)⊙hₜ₋₁ + zₜ⊙h̃ₜ

 


 
Pasta / cheese analogy from the slides

  
The source sentence contrasts “Samosa” context with later “Pasta” and “Cheese.” Reset gate suppresses irrelevant old memory (“Samosa”) while forming the new candidate; update gate decides how much of the new “Pasta/Cheese” candidate replaces the old hidden state. The final hₜ therefore reflects the newer Italian-food context.

M5Σ
Optimization for long-term dependencies + explicit memory
The final Module-5 slides list a wide set of strategies. Know the role of each; only gradient clipping and explicit memory are developed in detail.


 

  
RNN / LSTM / GRU
Use recurrent memory and gated units to preserve useful information over time.

  
Attention
Self-attention and multi-head attention let the model directly focus on relevant sequence positions.

  
Positional encoding
Maintains sequence position/order information in Transformer-style models.

  
Hierarchical models
Process sequence information at multiple granularities to capture local and global dependencies.

  
Dilated convolutions
Capture wider context without proportionally increasing parameter count.

  
Memory-augmented networks
Use an external memory component; source names Neural Turing Machines and Differentiable Neural Computers.

  
Regularization
Reduce overfitting that can make models less reliable on long-term dependencies.

  
Feature engineering / augmentation
Create long-trend features or expand training examples to expose models to varied long dependencies.

  
Normalization / curriculum / advanced arch
Batch/layer normalization, training from simpler to harder sequences, and architectures such as Transformers/memory networks are named.

 


 
Gradient clipping

  
When gradients become extremely large, gradient clipping imposes a threshold / rescales values into a manageable range. The slide emphasizes that the goal is to control magnitude, not alter the intended descent direction. This stabilizes learning and prevents extreme parameter updates/divergence.

 


 
Explicit memory

  
Standard RNN/LSTM memory is implicit inside hidden/cell state and has finite context. Explicit memory adds a separate component the model can read from and write to—similar to external computer memory—so information can be stored and retrieved over longer periods.

  
The source motivates it for story understanding, dialogue systems and reasoning, and mentions Transformer attention as a memory-retrieval mechanism. Applications named include QA, chatbots, reasoning/planning, long-text understanding and robotics/control.

Rapid drill · no notes until you answer
These questions are deliberately concentrated on the most examinable mechanics in the ZIP.


 
1. 32×32×3 input, 5×5 filters, stride 1, no padding, 6 filters. Output?
28×28×6.

 
2. Why does padding matter beyond “same size”?
Without padding, repeated convolution shrinks maps and border pixels participate in fewer windows; padding preserves border information/participation.

 
3. Conv params for 3×3, Cin=3, Cout=10 with one bias/filter?
(3×3×3+1)×10=280.

 
4. Which Module-3 layers have zero trainable parameters?
ReLU/activation, max/average pooling and flatten. The source also treats softmax itself as no trainable weights; the preceding dense output weights are trainable.

 
5. Inception's 1×1 convolution solves what?
It projects/reduces channel depth before expensive 3×3/5×5 branches, cutting parameters and computation while preserving spatial dimensions.

 
6. ResNet's defining equation?
y=F(x)+x.

 
7. RNN hidden-state equation in the slides?
hₜ=tanh(Wₕₕhₜ₋₁+Wₓₕxₜ) in the conceptual slide; another numerical uses sigmoid with bias.

 
8. Source 3-step RNN h₃ and y₃ approximately?
h₃≈0.785; y₃≈0.864.

 
9. Four BPTT stages?
Forward pass → total loss → backward through time → weight update.

 
10. BPTT source updated weights after one step?
Wₓ=.80862, Wₕ=.51517, Wₒ=1.01254.

 
11. What makes BRNN different?
It processes the same sequence in forward and backward directions, using past and future context.

 
12. Autoencoder's three conceptual parts?
Encoder → latent/bottleneck code → decoder.

 
13. Seq2Seq decoder uses what to generate each output?
The encoder context vector plus previous generated output / decoder state, one step at a time.

 
14. BERT input embedding is the sum of what three embeddings?
Token + positional + segment embeddings.

 
15. BERT MLM 80/10/10 rule?
Of selected (~15%) tokens: 80% [MASK], 10% random word, 10% unchanged.

 
16. LSTM cell update?
Cₜ=fₜ⊙Cₜ₋₁+iₜ⊙C̃ₜ.

 
17. GRU has which gates and what state is absent?
Update and reset gates; there is no separate cell state Cₜ.

 
18. Echo State Network: which weights are trained?
Only output weights Wout; the reservoir recurrent connections stay fixed/random in the source model.

 
19. What does gradient clipping actually control?
Excessive gradient magnitude, to prevent unstable/exploding parameter updates while preserving the intended gradient direction.

 
20. RecNN vs RNN?
RecNN models tree/hierarchical structure; RNN models sequential/time-ordered structure.
