M3

Data reduction · types and exactly what each type reduces

Data reduction gives a smaller representation while preserving the same or similar analytical result. Your supplied preprocessing material develops dimensionality reduction, parametric/numerosity reduction and aggregation methods.

Dimensionality

PCA

Transforms n correlated original attributes into a smaller set k ≤ n of new orthogonal/uncorrelated principal components. It creates new variables; it does not merely select old ones.

Dimensionality

Attribute subset selection

Removes irrelevant or redundant attributes while keeping the original attributes that matter. Exhaustive search has 2ⁿ subsets, so greedy heuristics are used.

Parametric

Regression

Replace a large set of raw points by model parameters. The source gives simple linear y = wx+b, multiple linear, and log-linear models.

Numerosity

Histograms

Approximate the data distribution using bins rather than storing every observation individually.

Numerosity

Clustering

Group similar objects and replace raw data by a cluster centroid or cluster summary.

Numerosity

Sampling

Analyze a representative subset rather than the entire dataset. The source lists SRSWOR, SRSWR, cluster sampling and stratified sampling.

Aggregation

Data cube aggregation

Summarize detailed data at a higher level—for example quarterly sales rolled into annual sales.

Construction

Attribute construction

Create useful new attributes from existing ones; the source example is Area = Height × Width.

Why

What reduction buys you

Lower storage and processing cost, fewer attributes/records, and a representation that still supports the intended analysis.

PCA · the step-by-step algorithm and the supplied numerical

Key idea: principal components are new linear combinations. PC1 captures the largest variance; PC2 the next largest, and so on.

  1. Normalize / scale attributes when their ranges differ, so one attribute does not dominate.
  2. Compute orthonormal component directions: unit-length vectors perpendicular to one another.
  3. Sort components by variance explained.
  4. Keep the high-variance components and discard low-variance components.

Attribute subset selection · the four methods in the source

Problem: with n attributes there are 2ⁿ possible subsets, so exhaustive search becomes infeasible.

Stepwise forward selection

Begin with no attributes. Repeatedly add the attribute that gives the best improvement.

∅ → {A1} → {A1,A3} → {A1,A3,A4} …

Stepwise backward elimination

Begin with all attributes. Repeatedly remove the least useful attribute.

{A1,A2,A3,A4,A5} → … → smaller subset

Combined approach

Add the best and remove the worst at each step.

Decision-tree induction

Attributes used by the tree are treated as selected; unused attributes are irrelevant for that induced tree.

Normalization · formulas, substitution, interpretation

Your core preprocessing slides explicitly teach three normalization techniques: min–max, z-score, and decimal scaling. Know all three and be able to substitute values cleanly.

1

Min–max normalization

v' = [(v−minA)/(maxA−minA)](new_maxA−new_minA)+new_minA

Maps a value from its old range into a specified new range.

Income: 12,000…98,000 → [0,1]
v=73,600 ⇒ (73,600−12,000)/(98,000−12,000)=0.716
2

Z-score normalization

v' = (v−μA)/σA

Centers by the mean and scales by standard deviation.

μ=54,000, σ=16,000, v=73,600
(73,600−54,000)/16,000=1.225
3

Decimal scaling

v' = v / 10ʲ

Choose the smallest integer j such that max(|v'|)<1.

Source example: 986 → 0.986 with j=3.
How to choose quicklyIf the question gives an explicit target range, use min–max. If it gives μ and σ or asks for standardization, use z-score. If it asks decimal scaling, choose j from the largest absolute value.

Discretization · theory + numerical workflow

Discretization reduces the number of values of a continuous attribute by replacing numeric ranges with interval labels. It is both a reduction technique and a preparation step for algorithms that require categorical attributes.

Binning · unsupervised

Equal-width: fixed interval size. Equal-frequency: approximately the same number of observations in each bin.

Histogram-based

Recursively use histogram bins to form a concept hierarchy.

Clustering-based

Clusters form the intervals: observations assigned to the same cluster receive the same discretized region/label.

Decision-tree based

Supervised. Choose split points that improve class separation / reduce class impurity.

ChiMerge

Supervised, bottom-up. Uses a χ² test and merges adjacent intervals with similar class distributions.

Concept hierarchy

Replace lower-level values with higher-level concepts—for example age values → young / middle-aged / senior.

Association rules · the concepts underneath Apriori and FP-Growth

FP-Growth makes much more sense when support and transaction structure are automatic to you.

Frequent pattern

A pattern that occurs frequently in data. It can be an itemset, sequence or structure.

Frequent itemset

A set of items that appear together often in a transactional dataset.

Support count

X.count = number of transactions containing itemset X.

Support

support(X→Y) = count(X ∪ Y) / total transactions

Probability/fraction that a transaction contains both the antecedent and consequent items.

Confidence

confidence(X→Y) = count(X ∪ Y) / count(X)

Conditional probability that a transaction containing X also contains Y.

Exact support/confidence examples from the association slides

Bag & Uniform: the slides give support({Bag,Uniform}) = 5/10 = 0.5. Bag occurs 8 times, so confidence(Bag→Uniform) = 5/8 = 0.625.

A→C example: 4 transactions: ABC, AC, AD, BEF. A occurs 3/4=75%, C occurs 2/4=50%, AC occurs 2/4=50%.

support(A→C)=2/4=50%
confidence(A→C)=2/3=66.6%

Road-map concepts that can appear as short theory

The source distinguishes Boolean vs quantitative associations, single-dimensional vs multidimensional associations, and single-level vs multilevel analysis. Market-basket data can be represented as Boolean presence/absence vectors.

Closed vs maximal frequent patterns · explicitly taught in the Apriori/FP-Growth deck

A long frequent itemset can imply an enormous number of frequent subpatterns, so the source introduces compact pattern families.

Closed frequent itemset: frequent X with no proper super-pattern Y having the same support as X. The source describes closed patterns as a lossless compression of frequent patterns.

Max-pattern / maximal frequent itemset: frequent X with no frequent proper super-pattern.

DifferenceClosed asks “same support?”; maximal asks “any frequent superset at all?” Every maximal pattern is closed under the usual definitions, but not every closed pattern is maximal.

Why Apriori can be slow + source improvements

Main bottlenecks: huge candidate sets and multiple database scans. Source improvements: transaction reduction, partitioning, sampling, and dynamic itemset counting.

Hash-tree support counting · why it appears

The source asks why candidate support counting is hard: candidate sets can be huge and one transaction can contain many candidates. Its solution stores candidates in a hash tree: leaf nodes contain candidate itemsets and counts; internal nodes contain hash tables; a subset function finds candidates contained in each transaction.

Apriori efficiency improvements · all four in the association slides
  • Transaction reduction: a transaction containing no frequent k-itemset is useless for later scans.
  • Partitioning: an itemset frequent globally must be frequent in at least one partition.
  • Sampling: mine a subset with a lower support threshold plus a completeness check.
  • Dynamic itemset counting: introduce new candidates at intermediate points while scanning.

FP-Growth · the full numerical you should be able to reproduce

This is one of your highest-priority questions. Learn the two scans, global support order, ordered transactions, tree insertion, conditional pattern bases, conditional FP-trees and generated patterns.

Core ideaFP-Growth uses divide-and-conquer. It compresses frequent-item information into an FP-tree, then mines smaller conditional databases rather than generating huge candidate sets like Apriori.
  1. First scan: count every item and discard items below minimum support.
  2. Sort frequent items globally by descending support.
  3. Second scan: reorder each transaction using that global order.
  4. Insert each ordered transaction into the FP-tree. Shared prefixes share nodes; increment counts instead of duplicating the prefix.
  5. Mine from the least-frequent suffix upward. For each suffix, collect all prefix paths → conditional pattern base.
  6. Prune infrequent items in the conditional base and build the conditional FP-tree.
  7. Concatenate the suffix with frequent patterns found in that conditional tree.

    2.

    4. 
   
  4. Recursively repeat for each child subset.
    5.

    6.

    7.

    8.

K-means · strengths, weaknesses, initialization and k

  
The bundle contains several K-means decks. The recurring algorithm is: choose k centroids → assign by distance → recompute centroids → repeat. The source notes different initializations can yield different clusterings.

  
Strength: relatively efficient; one slide gives O(tkn) with n objects, k clusters and t iterations. Weaknesses: requires k in advance, mean must be meaningful, sensitive to noise/outliers, and poor for non-convex clusters.

  
The earlier K-means deck also discusses getting k right with examples/plots and includes a medicine/malignant-vs-benign numerical using Euclidean distance.

 


 
Nearest-neighbor clustering · threshold version

  
The k-means-2 deck teaches a separate incremental clustering idea: k is not fixed in advance. Choose threshold t; when a new point arrives, add it to the nearest existing cluster if it lies within t, otherwise create a new cluster. The source emphasizes that choosing t is difficult and different t values yield different clusterings.

 


 
DBSCAN concepts beyond the final cluster answer

  
DBSCAN measures density by the number of objects within ε. Core points have dense neighborhoods; clusters are formed by connecting core points and density-reachable neighbors. Border points are not core but lie in a core neighborhood; noise does not become density-reachable from a cluster.

  
The later PDF gives the exact ε-neighbor table, core points P2/P5/P11, two final clusters and P9 as noise, as already reproduced above.
